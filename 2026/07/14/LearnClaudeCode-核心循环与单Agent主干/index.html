Claude Code 的核心：所有机制挂在同一个循环上

2026-07-14- 2026-07-31
2.2k- 8m
课程笔记-学习Agent大模型Claude Code

本文整理自 Learn Claude Code 课程的学习笔记。课程把一个 Claude Code 式的编码智能体拆成 20 步，每步只往主循环里加一个机制。本文聚焦最核心的理念和前六步，从「会说话」到「会干活」的单 Agent 主干。

一句话理解 Claude Code 的设计哲学

机制很多，循环一个。

一个能长期工作的编码智能体，需要同时拥有工具分发与权限边界、Hook 扩展点、待办计划与任务图、技能/记忆/系统提示词组装、上下文压缩与错误恢复、后台任务与定时调度、多智能体协作、工作区隔离、MCP 外部工具接入。听起来很复杂，但 Claude Code 的设计思路是：这些机制全都挂在同一个 while True 循环的不同位置上。循环本体从头到尾几乎没变，变的是循环周围的 harness 越来越完整。

循环的核心逻辑可以浓缩成一段话：

调用模型 → 检查响应里有没有 tool_use → 有就执行工具 → 把结果追加回 messages → 继续下一轮。

Agent 的核心不是「模型很聪明」，而是「系统持续把现实结果喂回模型」。

最小闭环：130 行代码让模型「会干活」

工具路由：加工具不改循环

权限系统：意图先过安全闸门

当工具越来越多，执行命令的风险也越来越高。rm -rf / 和 cat README.md 应该有不同的信任级别。Claude Code 在工具执行前插了三道闸门：

第一道：deny（直接拒绝）。 黑名单规则，比如「永远不允许 sudo」。

第二道：rules（规则匹配）。 看命令是否匹配预设规则，比如「允许读取但禁止删除」。

第三道：ask（问用户）。 前两道都放行后，如果配置了交互模式，就把命令展示给用户确认。

这三道闸门串在一起，形成一条管线。模型发出的每个工具调用都要先穿过这条管线，才能到达实际执行函数。主循环不需要知道权限系统的存在，权限系统也不需要知道主循环的存在，它们通过「工具执行前拦截」这一个接口点连接。

Hook 系统：不改主循环也能扩展

权限是「工具执行前」的拦截，但 Agent 生命周期的其他节点呢？比如「用户提交 prompt 之前」想注入一些上下文，「工具执行完之后」想做日志记录，「整个循环停止之后」想做清理。

Claude Code 的做法是定义四个 Hook 扩展点，覆盖一个完整轮次的始终：

  • UserPromptSubmit：用户输入提交前，可以修改或注入内容
  • PreToolUse：工具执行前（权限闸门之外的第二层拦截）
  • PostToolUse：工具执行后，可以修改返回值或记录日志
  • Stop：循环结束时，可以做清理或收尾

Hook 的设计理念是：外部代码可以在不修改主循环源码的前提下，在循环的特定位置插入自定义逻辑。 这让 Agent 变成了一个可扩展的平台，而不是一个封闭的黑盒。

待办写入：让 Agent 学会做计划

模型在工作过程中经常需要记录待办事项：先做 A，再做 B，最后检查 C。如果没有一种持久化的方式记录这些计划，模型就只能靠对话历史里的自然语言「记住」任务列表，随着上下文增长很容易遗漏。

模型可以往里写任务、标记完成状态、更新内容。系统还有一个 nag reminder 机制：如果模型写了待办但迟迟不执行，系统会主动提醒它「你还有未完成的任务」。

待办写入的本质是给模型一个外部记忆，让它在多轮工具调用之间不会丢失对全局计划的感知。

子代理：子任务使用全新上下文

当主 Agent 遇到一个可以独立完成的子任务时（比如「搜索这个函数的定义」），如果让主 Agent 自己去做，会消耗主上下文的 token。更好的做法是委派一个子代理去完成，它有自己的独立消息历史，做完后只把结果摘要返回。

子代理的关键特征：隔离的消息历史。主 Agent 看不到子代理内部的对话细节，子代理也看不到主 Agent 的完整上下文，它只收到一段任务描述，完成后返回一段结果。这样既节省了 token，又避免了不同任务之间的上下文污染。

小结：六个机制，一个循环

回顾这一篇覆盖的六个机制：

机制 挂在循环的哪个位置 解决什么问题
Agent 循环 循环本身 把模型从「会说」变成「会做」
工具路由 工具执行环节 加工具不改循环
权限闸门 工具执行前 拦截危险操作
Hook 扩展点 循环各节点 不改源码也能扩展
待办写入 作为工具被调用 给模型外部记忆
子代理 作为工具被调用 隔离上下文、节省 token

注意一个规律：后面五个机制，有的是在工具执行前插入（权限），有的是在循环各节点插入（Hook），有的干脆就是作为一个工具被调用（待办、子代理）。不管挂在哪，循环本体始终是同一个 while True。

这就是 Claude Code 最核心的设计理念。后面的章节会继续往这个循环上挂更多机制，技能按需加载、上下文压缩、长期记忆、系统提示词动态装配、错误恢复、后台任务、多 Agent 协作，但循环本身不变。
